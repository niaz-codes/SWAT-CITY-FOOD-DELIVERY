# Changelog

## [Unreleased]

- Android builds work again on Expo SDK 58. EAS failed with `EAS_BUILD_UNKNOWN_GRADLE_ERROR` because `package.json` had been upgraded to SDK 58 / RN 0.88 while the committed `android/` project was still the SDK 57 prebuild. Regenerated it with `expo prebuild --clean` and made the parts prebuild wipes or mis-writes self-healing: a new `plugins/withGoogleServices.js` re-applies the Google Services Gradle plugin and restores `google-services.json` (now kept at `firebase/google-services.json`), `plugins/withAndroidReleaseSigning.js` regenerates `keystore.properties` and the keystore from `credentials.json`, and `scripts/fix-android-manifest.js` repairs the malformed `<root>`-wrapped `AndroidManifest.xml` that SDK 58 emits (wired into `npm run prebuild` and the EAS `eas-build-post-install` hook). See `DEPLOYMENT.md`.
- The `EXPO_PUBLIC_API_URL` fallback in `src/services/client.ts` now points at the live backend instead of the Android emulator loopback (`10.0.2.2`), so a build with the variable unset can no longer ship a dead URL to a real device.
- Rider app: vehicle management and map-based base location. Riders can now switch vehicle type and update their registration number from **My vehicle**, and set their base pin from a searchable map (**Base location**). Vehicle changes are admin-approved — the proposal is parked on the profile as `pendingVehicle` and the live vehicle fields (used by dispatch and the admin map) only change on approval, with registration numbers checked for uniqueness across riders. New endpoints `POST /rider/vehicle` and `POST /rider/base-location`, plus admin `POST /admin/riders/:id/vehicle/approve|reject`, and a `pendingVehicle` jsonb column on `rider_profiles`. See `RIDER_MANAGEMENT.md`.
- Supabase Auth OTP emails now show the 6-digit code (`{{ .Token }}`) instead of a "Confirm your email address" link. The default "Confirm signup" / "Magic Link" templates sent a single-use link whose token was already consumed or superseded (and with no allowed redirect it fell back to the default `http://localhost:3000` Site URL — the `otp_expired` screen). Added `npm run auth:config` (`backend/src/scripts/supabase-auth-config.ts`) to apply code-only templates, the production Site URL, allowed redirects (`swatcity://**`, Expo web dev), 6-digit codes and a 600-second expiry in one call; set `AUTH_EMAIL_REDIRECT_URL` only if a template keeps a link. Verification now tells an expired/used code apart from a wrong one and points at "Resend code", and OTP logs no longer include email addresses.
- Email OTP codes (login, registration, password reset) are now generated, delivered and verified by Supabase Auth instead of the backend SMTP transport. Configure delivery in the Supabase dashboard (Authentication → Emails → SMTP); Gmail SMTP (`smtp.gmail.com:587` + Google App Password) is the documented setup because the built-in Supabase sender does not reliably reach Gmail. The optional "password changed" notice now uses generic `SMTP_*` env vars (formerly `BREVO_*`) and can point at any provider.
- OTP resilience fixes: a failed email send no longer burns a rate-limit slot (previously repeated failures locked the account for 15 minutes with a misleading "too many codes" error), a successful code verification now clears the request window so a legitimate user is never locked out by their own earlier attempts, and resending reports a failed send instead of pretending the code is on its way.
- Removed the temporary OTP diagnostic/maintenance scripts once Supabase Auth took over code generation and checking.
- Added project documentation (.md files) for AI agents.
